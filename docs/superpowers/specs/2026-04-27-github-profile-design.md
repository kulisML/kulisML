# kulisML GitHub Profile Design

## Executive Summary

Build a public GitHub profile README for `kulisML` that acts like a bright personal product page. The profile should position Kulis as an aspiring Machine Learning Engineer with strong AI, full-stack, automation, and frontend product energy.

## Goals

- Create a memorable bright AI product-builder first impression.
- Help clients and recruiters understand the profile in under 20 seconds.
- Show confidence without overstating seniority.
- Keep all current repositories visible while making the best work stand out first.
- Include restrained dynamic elements: premium local SVG hero animation, GitHub stats, activity graph, and contribution snake.

## Audience

Primary audience:

- Clients looking for a developer who can build AI-powered products and automation systems.
- Recruiters looking for junior or aspiring ML/full-stack talent.

Secondary audience:

- Developers and technical reviewers checking the repository history and stack.

## Voice And Positioning

Hero line:

`kulissssss / kulisML - AI Product Builder crafting ML systems, automations, and polished web experiences`

Supporting tone:

- Friendly and human.
- Bright, playful, and product-focused.
- Honest about being an aspiring Machine Learning Engineer.
- Focused on shipping useful systems, not only collecting badges.

## Visual Direction

- Style: bright 3D product-builder identity inspired by a colorful AI assistant/product banner reference.
- Palette: white base, ink headline, coral, teal, yellow, purple, and cobalt accents.
- Hero: custom animated SVG with colorful waves, AI assistant, workflow cards, code panel, ML chart, database blocks, and soft product shadows.
- Dynamic elements:
  - Local bright hero SVG animation for roles and mission.
  - Light-themed GitHub stats cards for credibility.
  - Light-themed activity graph for motion and proof of work.
  - Contribution snake generated by GitHub Actions.

## Content Structure

1. Custom bright product hero banner.
2. Centered hero title and contact badges.
3. Product Studio section.
4. Three pillars:
   - AI / ML
   - Full-Stack Systems
   - Frontend Craft
5. Curated tech stack.
6. Featured Builds:
   - `gitlab-telegram`
   - `bulbai2`
   - `FocusGuard`
   - `HakatonHungerGames`
7. Product Pipeline section.
8. Project Shelf section with every visible repository.
9. Motion Layer with GitHub stats and contribution snake.
10. Contact call-to-action.

## Repository Research Notes

- GitHub shows a profile README when the account has a public repository named exactly like the username with a non-empty root `README.md`.
- Current profile username: `kulisML`.
- Current public profile has 14 repositories and pinned projects: `FocusGuard`, `HakatonHungerGames`, `hakanot4`, `gitlab-telegram`.
- `gitlab-telegram` already has strong README material and positions well as an automation/backend project.
- `bulbai2` has a clear technical concept: STL-first bulbous bow generation, evaluation, and reporting.
- Several repositories have no descriptions, so the profile should avoid overclaiming and frame them as labs, hackathon work, or experiments.

## Acceptance Criteria

- Root `README.md` exists and is non-empty.
- README contains the selected hero positioning.
- README includes Telegram and email contacts.
- README includes the three skill pillars.
- README includes all currently visible repositories.
- README includes the bright product hero animation, stats, and contribution snake references.
- README avoids dark/space styling and uses light product colors.
- README does not include external repo pin cards that can show `No description provided`.
- README does not include the external typing SVG widget.
- `assets/bright-product-hero.svg` exists and renders as an SVG image.
- `.github/workflows/snake.yml` exists and generates light/dark snake SVGs into the `output` branch.
- A local validation script can check the required profile content.

## Out Of Scope

- Publishing to GitHub automatically.
- Creating LinkedIn or portfolio links before they exist.
- Renaming or privatizing existing repositories.
- Editing existing project READMEs.
